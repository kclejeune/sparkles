# Per-query costs after stage 4 on forge

A manual report of lane 679's A/Bs on forge, alone under its benchmark lock. Each run
compares a base A and a candidate B twice, once with the candidate second in A,B,B,A rounds
and once with it first, and each table gives the candidate's server execution time over the
base's as the square root of the two runs' median per-round ratios, with a 95% bootstrap
interval over the rounds. This is the rule of `scripts/x08-gates/combine.py`, here without
its ten-round minimum, which only f4 falls below. The base and candidate columns are each
build's median over both runs. Decision D4's rule for queries under 0.3 ms passes a query
whose upper bound is at most 1.02 or whose added time is at most 0.5 µs. Every run's two
servers returned the same answer fingerprints, which each `answers.tsv` lists, and no
request failed.
