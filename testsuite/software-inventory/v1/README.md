# Software inventory fixture resources

These resources are an incomplete, offline fixture corpus. They do not implement a scanner or make claims about deployed artifacts, runtime inclusion, exploitability, authenticated availability or maintained current results. No advisory concerns a real package. The synthetic names and advisory are reserved for this fixture.

The real lockfile is an immutable byte copy observed at the commit in the manifest and verified again at the separately recorded base. Its full projection comes from the independently adjudicated oracle. It describes Cargo lock resolution, not selected build features. The synthetic registry checksums are dummy declarations and no package artifacts were verified.

The before and after locks, initial advisory, correction and withdrawal are separate immutable revisions. Withdrawal is inactive historical evidence, not an assertion of safety. The case catalog preserves the adjudicated outcomes and is not generated by a matcher. The framing script calculates bytes only from explicit fields. It has been checked against the seven independently adjudicated vectors.

This corpus is not ready for matcher adoption. Its case index names concrete inputs or explicit operation envelopes for the adjudicated controls. The 75 version inputs use the independently adjudicated range profiles and expected statuses. The resource diff, full projection, selector slices, keyed records and exact query bindings require independent review and remediation before matcher work. No engine feature is completed by these resources.

The TOML slice goldens record the observed byte spans from `toml::Spanned<String>` in toml 1.1.6. The half-open ranges include string delimiters. Independent UTF-8 and TOML decoding checks cover basic and literal escapes, an astral character before a field and CRLF bytes. The JSON slice goldens follow the existing C25 JSON lexical UTF-8 method; the fixture does not define a second selector.

The identity contract fixes fixture-local channel names, method versions and a mapping from framed keys to local record IRIs. A source revision frame contains a bare lowercase SHA-256 digest. The C25 `contentDigest` literal uses a separate `sha256:` prefix. The local IRIs do not claim global package or issuer identity. A later application mapping may relate these records to other representations without changing retained occurrence keys.

The RDF dataset is a manually specified offline example built from the retained tuples and adjudicated outcomes. Its five query answer files describe exact RDF terms as unordered result multisets. The two nonassertion queries both return false for the positive fixture. The asserted-triple control returns true for both and demonstrates that these queries can detect projection into either graph. No availability receipt, accepted projection or stored-fact coordinate is present.

The bounded-operation controls include versioned deterministic byte recipes with
supported boundary and limit-plus-one siblings. They fix byte counts, source digests,
parsed-record counts, the intended failure stage and cancellation injection events.
The materializer creates only supplied fixture bytes and refuses an existing output
path. It computes no membership, applicability or evaluation answer. Materialize its
large controls under `.artifacts` rather than checking repeated megabytes into Git.
The total-expansion siblings reach exactly 100,000 and 100,001 outgoing occurrence
visits while remaining below the other input, depth and per-target path bounds.

The primary and mirrored advisory have separate framed advisory identities and
separate offline claim occurrences with exact source-revision selections. Both retain
the common declared origin. The lineage query exposes their claim and evidence IDs,
with independence left unknown rather than counted as two votes. The shared raw bytes
do not collapse source channels or occurrence identity.
